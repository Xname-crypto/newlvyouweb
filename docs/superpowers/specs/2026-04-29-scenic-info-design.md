# 景点信息补全设计

日期：2026-04-29

## 目标

基于现有 Excel 文件 `旅游景点.xlsx`，补全每个景点的两个缺失字段：

- `是否需要预定`
- `开放时间`

本次交付只修改这两个业务字段，不向工作簿新增其他展示列。为避免破坏原始数据，脚本输出一个新文件 `旅游景点_补全.xlsx`，原文件保持不变。

## 当前上下文

- 工作区根目录存在文件 `旅游景点.xlsx`
- 当前工作簿只有 1 个工作表 `Sheet1`
- 当前表头为：
  - `城市`
  - `名称`
  - `星级`
  - `评分`
  - `价格`
  - `销量`
  - `省/市/区`
  - `坐标`
  - `简介`
  - `是否免费`
  - `具体地址`
- 当前总行数约 2444 行
- 项目中已经存在基础抓取代码 `backend/data_engine/crawler.py`，但它偏向通用页面抓取，不直接适合本次 Excel 批量补全任务

## 非目标

- 不补充 `信息来源`、`抓取日期` 等展示列
- 不直接覆盖原始 Excel
- 不尝试补齐所有旅游字段，只处理 `是否需要预定` 与 `开放时间`
- 不把搜索引擎摘要直接视为最终事实来源

## 数据来源策略

采用“官方优先，平台回退”的分层策略：

1. 优先景区官方站点、景区官方公告、官方票务说明页
2. 抓不到时回退到高可信旅游平台详情页，如携程、同程、美团等
3. 搜索引擎结果页仅用于发现候选链接，不直接作为回填值来源

原因：

- `开放时间` 常存在节假日调整，官方信息更可靠
- `是否需要预定` 往往出现在购票须知、入园须知、预约公告中
- 单平台方案虽然实现快，但准确性和覆盖率不稳定

## 输出规则

### 目标列

- 如果 `是否需要预定` 不存在，则在表尾新增
- 如果 `开放时间` 不存在，则在表尾新增

### 值标准化

`是否需要预定` 统一写入以下三种值之一：

- `是`
- `否`
- `未知`

`开放时间` 统一写入简洁文本，优先保留规则性描述，例如：

- `周二至周日 09:00-17:00，周一闭馆`
- `09:00-17:00`
- `节假日另行公告`

### 保守写入原则

满足以下条件之一时，不强行写确定值：

- 页面未找到明确字段
- 多个高可信来源互相冲突
- 页面内容明显是过期活动页且无法确认当前规则

此时处理方式固定为：

- `是否需要预定` 写 `未知`
- `开放时间` 留空

## 实现方案

实现一个专用脚本：

- `scripts/fill_scenic_info.py`

### 模块职责

1. **Excel 读取与写回**
   - 读取原始工作簿与表头
   - 定位或新增目标列
   - 按行更新结果并输出新工作簿

2. **候选查询构造**
   - 以 `城市 + 名称` 为主查询词
   - 必要时拼接 `开放时间`、`预约`、`预定` 等限定词
   - 对名称做轻量清洗，避免无意义括号和营销后缀影响搜索

3. **候选来源选择**
   - 优先匹配官方域名与官方公告类页面
   - 回退到高可信平台详情页
   - 对明显无关页面、聚合页、论坛页直接过滤

4. **字段提取与归一化**
   - 从页面文本中抽取 `开放时间`
   - 从“预约须知 / 购票须知 / 入园须知 / 温馨提示”等上下文判断 `是否需要预定`
   - 将原始文本归一化为标准输出格式

5. **批处理控制**
   - 限速
   - 失败重试
   - 断点续跑
   - 可选样本模式，先处理少量景点验证结果

## 处理流程

1. 读取 `旅游景点.xlsx`
2. 遍历每一行景点
3. 使用 `城市 + 名称` 构造检索请求
4. 获取候选页面列表
5. 按优先级选择页面：
   - 官方页优先
   - 平台页回退
6. 抓取页面正文
7. 提取 `是否需要预定` 与 `开放时间`
8. 归一化结果
9. 写入当前行
10. 周期性保存中间结果
11. 生成 `旅游景点_补全.xlsx`

## 抽取规则

### 是否需要预定

优先依据以下表述判断：

- 明确需要预约、实名预约、提前预约、分时预约：写 `是`
- 明确无需预约、免预约、可直接入园：写 `否`
- 仅提到“可购票”但没有明确预约要求：写 `未知`

### 开放时间

优先提取以下类型内容：

- 固定营业时间
- 周一闭馆等周期规则
- 节假日临时开放时间

归一化时保留最主要的当前有效规则，不在首版中尝试编码复杂节假日日历逻辑。若页面只给出短期节假日公告，需要谨慎判断是否适合覆盖常规开放时间。

## 可靠性策略

由于数据量约 2444 行，直接全量抓取存在误填与限流风险，实现阶段必须具备以下保护：

- 默认支持 `--limit` 参数，先跑样本
- 默认支持断点缓存，避免中途中断后从头开始
- 对同一景点保留原始抓取文本到本地缓存，便于复核
- 对提取失败和冲突结果记录原因
- 对高风险结果不写死为猜测值

## 错误处理

- 搜索失败：标记当前景点失败并继续后续行
- 页面抓取失败：切换候选来源或重试
- 提取失败：写 `未知` 或空值，依据最终固定策略执行
- Excel 写入异常：保留中间文件并停止，避免结果全部丢失

## 测试与验证

实现后按以下顺序验证：

1. 先对 5 到 10 个景点做样本跑通
2. 人工核对典型样本：
   - 官方站点能直接给出开放时间的景点
   - 官方站点没有明示预约要求、需要平台回退的景点
   - 信息不明确的景点
3. 确认列位置、编码、保存结果正常
4. 再执行更大批量任务
5. 最后生成完整补全文件

建议首批样本包含：

- 上海科技馆
- 上海迪士尼乐园
- 上海野生动物园

## 风险与取舍

- 搜索结果质量受景点名称歧义影响，必要时需要结合地址辅助判断
- 平台页面结构可能变化，因此抽取逻辑不能强依赖单一 CSS 结构
- 某些景点的预约政策随日期波动，首版只能抓取“当前可见规则”，不能保证长期稳定
- 若运行环境网络受限，实现阶段可能需要额外授权才能完成批量联网抓取

## 最终交付

实现完成后应产出：

- 脚本 `scripts/fill_scenic_info.py`
- 补全后的文件 `旅游景点_补全.xlsx`

原始文件 `旅游景点.xlsx` 不修改。
